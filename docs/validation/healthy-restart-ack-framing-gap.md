# Healthy restart ACK framing: decision required

The current `WindowsRestartIo` reads an exact requested byte count; `WindowsBrokerOperations::exchange` reads a 24-byte control ACK from the retained endpoint. A successful fixed-size read validates those bytes but does not establish that no additional bytes are buffered or will arrive later. EOF and process termination are not a `Closed` acknowledgement, and a matching first record alone does not establish uniqueness.

For A, a candidate sequence is: validate matching Stop ACK, read and validate the distinct parent-bound `Closed` record, require unforced A/job settlement, then require EOF on A's ACK stream before B launch. Any additional byte, missing `Closed`, failed read, forced termination or incomplete settlement fails closed. This requires the owned child ACK writer to close on A exit and must be checked against the actual handle-ownership path. The parent must preserve the original 180-second overall deadline and cleanup reserve.

B's ACK channel is also used for later cancellation acknowledgements. Requiring EOF immediately after `GrantAccepted` would make that later exchange impossible. A framed parser can reject malformed, trailing or duplicate records when they are observed, but it cannot prove that a duplicate will never arrive later while the stream remains open. A candidate is an explicit parent `RestorePermit` on the existing control channel after matching `GrantAccepted`; B parses and applies controls before restoration dispatch. Such a permit binds authorization to the parent and current intent, but it still must not be described as proof that no delayed duplicate exists.

The decision must specify channel ownership/closure, how partial and multiple frames are consumed, behavior when cancellation and acceptance cross, and whether duplicate acceptance is a protocol failure after the permit. No new independent supervisor or state machine is proposed. Until this is resolved and tested on actual adapters, B launch/restoration remains fail-closed; no native execution or CI run is authorized by this note.
