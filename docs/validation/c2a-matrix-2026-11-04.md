# Windows C2a diagnostic matrix: failure checkpoint

The five contained diagnostic cases were run in Windows Debug and Release at
source revision `8dbf30d82e62c507e61155317be8f93a5b9158bf`, using Qt 6.9.3
and MSVC 2022. **Three of five cases passed in each configuration; two failed.**
The C2a gate is incomplete. These results do not establish C2b, G2 creation,
production recovery, or Linux or macOS behavior.

| Case | Debug | Release |
| --- | --- | --- |
| Create failure | 3 passed, 0 failed, 0 skipped; complete footer | 3 passed, 0 failed, 0 skipped; complete footer |
| Terminal retirement | 3 passed, 0 failed, 0 skipped; complete footer | 3 passed, 0 failed, 0 skipped; complete footer |
| Stop with pending hook | 3 passed, 0 failed, 0 skipped; complete footer | 3 passed, 0 failed, 0 skipped; complete footer |
| Render failure | Failed; no QTest footer | Failed; no QTest footer |
| Active retirement | Failed; no QTest footer | Failed; no QTest footer |

For every case the helper observed a known empty job both before and after
cleanup and made no termination request. The three passing cases exited 0;
the failing applications exited 1 and the helper reported overall failure.
The helper source maps that failure to exit 7; its own exit status was not
included in the retained helper stdout. No process-survival or forced-kill
claim is made from those failure logs.

The fixture executable SHA-256 values were
`8d91693aacd294bae7c0a9c6e810fade33a6daef46d2e9b376e80eb85cbd1074`
(Debug) and
`1810d0c790a3d1b1e4841fe64c80cdb54830f4fd9d7687f04001bdc221aee301`
(Release).

The create-failure records show generation 1, one create-stage failure with
raw error -18, consumed injection, and zero ready signals, Player binding,
callbacks, frees and retirement acknowledgements. The terminal-retirement
records show advancing playback before Stop, then force-window `no`, idle and
the exact unavailable current-VO result before the withheld job and the
same-generation retry. The blocked attempt records zero frees and ACKs; the
retry records one retirement while preserving the binding and using the
original context on the render worker.

The pending-hook records show one hook scheduled and pending when Stop was
accepted, then one continuation for the same hook ID with return 0. The
continuation was observed **before** the retirement ACK in these runs; they
do not prove a hook remained pending across that ACK.

Both failing cases logged the stuck-render diagnostic followed by `No render
context set` and a VO-window initialization critical. The render-failure case
then failed its diagnostic gate; its measured records show the injected
render error and, after retirement, an end-file event with reason 4 and error
-15. The active-retirement case failed its held-callback/unregister assertion
and did not write its scenario JSON. The ordering in the logs is observation,
not proof of cause. Neither failed case has a complete QTest footer.

The diagnostic guard was separately challenged in each configuration with an
intentional critical, a mixed-case stuck message and a mixed-case deadlock
message. Both sentinel runs produced the intended QTest failure, a complete
footer and totals of 2 passed, 1 failed and 0 skipped. The prior standalone
create-failure report observed no critical log, but its handler was installed
before QTest replaced it; that older run did not prove the guard was active.
The present matrix uses the corrected guard and the sentinel verifies it.
