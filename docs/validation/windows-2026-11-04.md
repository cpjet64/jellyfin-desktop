# Windows validation evidence — 2026-11-04

This report separates the local Windows results from cross-platform and
production acceptance. It does not establish that all upstream reports are
fixed or that a release has been published.

## Qt-only threaded rendering experiment

The standalone diagnostic built from integration commit
`9944c1c944e74622cce4870c00bb29fcdabbc40e` used Qt 6.9.3. The test executable's
SHA-256 was
`A1E35F18AE7088B26ECE70C6D805982E4C196F60A0A50A0151E912CEA852A8D2`.
QtTest reported **11 passed, 0 failed, 0 skipped**. The containing process exited
normally with code zero, without forced cleanup or remaining job processes.

The test exercised changing nonblank frames while the GUI thread was withheld,
thread and context ownership, cleanup ordering, early-failure cases, and
settlement of a pending readback request. Images were checked in memory; they
were not saved as image artifacts. The wrong-private-state case injects a
synthetic guard failure rather than corrupting Qt-owned state. The pending
readback case cancels a request flag before the synchronous worker readback; it
does not prove cancellation of an asynchronous GPU operation. The deliberately
blocked-cleanup case is an expected unsuccessful contained child process, not
a successful resource retirement.

This is Qt-only evidence. It does not exercise mpv renderer retirement or
reconstruction, establish playback recovery, or establish Linux or macOS
behavior. Production automatic recovery remains held for separate review.

Local evidence: `deps/w255-qt-proof/case/qtest.txt` in the integration worktree
and `deps/windows-validation-proof/w255-9944c1c/helper.log` under the repository
root. The former is the test report; the latter records process containment.
