**Status: UNQUALIFIED for the selected binary.** The candidate upstream source has a useful lock-based callback barrier, but the available evidence does not prove that the selected DLL was built from that exact source without relevant changes. No native free or positive retirement acknowledgement may depend on the candidate-source inference alone.

## Candidate upstream implementation

At the named [candidate revision, `vo_libmpv.c`](https://github.com/mpv-player/mpv/blob/01e2533f3143b8940857ca419b0b367f583e05ca/video/out/vo_libmpv.c):

- Lines 71–76 place the callback and context under `update_lock`. `update()` at 111–118 locks before checking and invoking the callback and unlocks only after the callback returns. Its direct callers in this translation unit are `dispatch_wakeup` at 138–143, installed on the dispatch queue at 168–169, and `draw_frame` at 451–464, after releasing the render-context lock.
- The only other direct invocation of the update callback in that file is the setter at 212–221. It holds the same lock while replacing callback and context, and immediately invokes a newly installed non-null callback under that lock. Unregistering with a null callback replaces both fields while holding the lock.
- For this exact source, if setter calls are serialized and the context remains alive, a null setter that returns has acquired the same lock after any already executing callback leaves it. A producer waiting before callback entry subsequently observes the null pointer under the lock. This is a source-level pre-entry and in-flight argument, not a guarantee about previously queued Qt work, a later re-registration, or the unverified selected DLL.
- Lines 42–45 document the native lock order, including core, VO, context lock, client API lock and update lock. The callback runs with `update_lock` held; calling the setter recursively, taking an incompatible lock, or waiting on work that needs it can deadlock. The public [render API threading contract](https://github.com/mpv-player/mpv/blob/01e2533f3143b8940857ca419b0b367f583e05ca/include/mpv/render.h#L52-L91) requires serialized render API calls and the original current GL context and warns about render-thread waits on normal API calls.
- `mpv_render_context_free()` at 233–299 makes the context unavailable for new acquisition, may initiate video teardown and process dispatch work while waiting for VO release, takes the context lock as an uninit barrier, drains remaining dispatch work, destroys the backend and synchronization objects, then frees the context. It does not itself establish that application callback storage or queued Qt deliveries remain safe. Unregister and application-side lifetime closure must precede free; do not hold an incompatible application lock across free.

## Application boundary and remaining proof

The inspected pinned MpvQt renderer registers `on_mpv_redraw` with the item pointer in `external/mpvqt/src/mpvrenderer.cpp` (29–31, 63–96). The callback queues `MpvAbstractItem::update` on that QObject; native callback return therefore does not mean the queued event has executed or been invalidated. The existing item destructor calls `mpv_render_context_free` at `external/mpvqt/src/mpvabstractitem.cpp` 46–50; that existing path is not proof of the diagnostic retirement protocol. The external-events build's patched renderer wrapper includes the reviewed MpvQt renderer source, while the intended diagnostic protocol is a separate retained-lifetime path.

For the selected generation, qualification must additionally establish the actual loaded DLL identity and source correspondence, original GL context lifetime/epoch and thread, closure of callback admission and queued deliveries, retained callback context through unregister return, no competing render calls or re-registration, and free return before a matching immutable ACK. Renderer destruction, an unavailable or replaced GL context, missing scheduling, uncertain free completion or late generation evidence remains a failure, not a positive ACK. These requirements are not established by this read-only audit or by injected tests.
