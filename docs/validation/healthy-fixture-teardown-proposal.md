# Healthy fixture teardown: test-only proposal

Status: **proposal only**. The synchronous-stop fixture remains held. This document authorizes no patch, build change, native run, or dependency modification. The selected route is bundled static MpvQt at `2ebbd38bf65d01be9c55d673ecd43c8bb9a6fc8e`, `MPVQT_EXTERNAL_EVENTS=OFF`, and `MPVQT_C2_DIAGNOSTIC_ONLY=OFF`; the installed SDK and pinned submodule must remain untouched. This route has not established safe teardown or a separate render thread.

## Existing evidence and gaps

The pinned `MpvRenderer::createFramebufferObject` creates the mpv render context and installs an update callback; `render` uses it on Qt's render path. The renderer has no retirement protocol. `MpvAbstractItem`'s destructor frees a non-null render context without checking the current GL context, unregisters the core wakeup, joins its worker, and destroys the core. Its private `MpvAbstractItemPrivate` holds the context, worker, controller and core pointers. Consequently ordinary stack unwinding or an early QtTest assertion can reach an unqualified free and core teardown.

The installed `mpv/render.h` requires serialized render API calls and, for OpenGL, the same current context used for creation. It requires render-context free before core destruction. These requirements do not establish that the fixture's render thread can progress while a GUI-thread synchronous command waits. The `EXTERNAL_EVENTS=OFF` Player path has neither `releaseMpvController` nor the external-mode null/generation guard in queued event and hook callbacks. Disconnecting a signal alone does not cancel already queued deliveries or contextless delayed hooks. The existing C2 diagnostic patch is useful prior art for a separate route; it does not prove equivalence or qualify this pristine mode.

## Proposed build-copy and access boundary

Only after separate approval, create an ignored, test-owned build copy from the verified pinned submodule and compile it solely into the isolated fixture target. Verify input hashes and patch applicability, then record the copied output hashes. Do not edit the submodule, installed SDK, or production application build. The proposed copy changes are:

1. In copied `mpvabstractitem_p.h`, add a test-only shared retirement state with the exact original context and render-thread identity, admission state, callback accounting and bounded evidence. In copied `mpvrenderer.cpp`, record the actual creation thread and current GL context immediately around successful creation; route update callbacks through that state; check its closed state in both rendering and framebuffer creation so no later queued update can render or recreate a context. Preserve the pinned normal rendering and synchronous-control behavior until retirement starts.
2. In copied `mpvabstractitem.h` and `.cpp`, add a fixture-only retirement request and completion signal. The implementation accesses `d_ptr->m_mpv_gl` in the defining class, not through a public production API or layout cast. A render job operates on the copied private state and clears that exact pointer after the one successful free. The copied destructor must not free or destroy a core after uncertain retirement; an explicit successful acknowledgement is the prerequisite for ordinary destruction. No private pointer is exposed through WebChannel.
3. Compile fixture-only copies of **both** `PlayerComponent.cpp` and `PlayerMpvEvents.cpp`, together with one matching fixture-only `PlayerComponent.h`. The copied OFF-mode `handleMpvEvents` must reject queued deliveries after release admission closes, before any `m_mpv` dereference. In the copied `PlayerMpvEvents.cpp`, replace the OFF-mode contextless delayed hook continuation with a fixture-owner/context-bound continuation carrying an accounted generation or lifetime token; a stale delivery must return before accessing the controller or core. The release barrier must close wakeup admission, unregister the existing callback, settle admitted callbacks, invalidate queued Player deliveries and delayed hooks, stop fixture-owned timers, and prove the worker's already queued controller work has passed a worker-thread fence. Prove the callback's pre-entry race as well as queued-work invalidation. Simply disconnecting or nulling `m_mpv` is insufficient. Preserve the original external-ON and normal application sources.
4. The OFF-mode `external/mpvrenderer-wrapper.cpp` hardwires `mpvqt/src/mpvrenderer.cpp` and therefore cannot compile the copied renderer. Generate a fixture-only wrapper that includes the existing `qt-wayland-compat.h` and the **verified copied** `mpvrenderer.cpp`, analogous in mechanics to the existing patched-wrapper template but without selecting external events or C2. Compile copied `mpvabstractitem.cpp` and `mpvcontroller.cpp` from that same copied MpvQt tree and put its matching public/private headers first for that fixture target. Confirm the generated wrapper and compiler dependency list resolve to the copy, not the submodule.
5. Add a fixture-only CMake path that builds a separate alternate static MpvQt target and alternate core from a source list replacing the two Player source files above, and links the fixture only to those alternates. Generate the fixture's Qt meta-object code and compile **every** alternate-core and fixture translation unit that sees `PlayerComponent` against the same copied header and diagnostic definitions. Do not link ordinary `jmp_core` or the original MpvQt library into that fixture, or mix their object files, class layouts, generated meta-objects or definitions with the alternates. Verify the actual link map/source list and include resolution as part of build review. Keep the selected static/OFF/OFF behavior and the existing application/package exclusions. The copied headers, private include directories, generated wrapper, alternate target/source lists, compile definitions, added signals and Player release barrier are the proposed private-access and build-copy changes; no new public Player method or production dependency patch is intended.

The copy must preserve the original Stop and load calls and return values. Any further private access or build substitution discovered during implementation is a new review item, not implicit approval.

## Ownership and teardown protocol

Allocate one fixture owner before binding. It owns the view, item, controller/core lifetime, secondary observer and cleanup state until completion. Its scenario body returns a result to a single cleanup coordinator; avoid `QVERIFY`/`QFAIL` returns inside a scope whose automatic destructors would tear down live graphics resources. Record the original test outcome separately from each cleanup outcome. Ordinary returns and exceptions after ownership begins both enter the same coordinator exactly once.

Before playback, capture the actual GUI/Player control thread, controller worker thread, renderer thread, creation-context identity and current context. Require that the thread executing the synchronous control is distinct from the thread servicing rendering, that each identity is stable, and that the context is the original one. A basic/same-thread render loop is a **pre-playback block**, not a fallback. Account for Qt scene graph invalidation or context replacement as failure; identities alone do not prove future scheduling or liveness.

While the core and render path are still available, seek a healthy terminal state. Preserve the scenario's original top-level Stop invocation and its actual result. If cleanup needs an additional Stop, issue at most one explicitly labelled cleanup Stop and record its separate result; never relabel it as the scenario Stop. Require successful Stop, `force-window=no` set/result and observed value, idle status/value, and current-VO unavailability, with bounded waits and the relevant event/entry identity. Idle alone is insufficient. Do not hold the render thread waiting for the core, and do not assume a timeout means termination.

After terminal confirmation, close render admission and reject queued redraw work. On the owning render thread with the original GL context current, unregister the update callback, settle all admitted callbacks and any already queued work, then free the exact context once and clear `d_ptr->m_mpv_gl`. A callback token/state must outlive all possible callback entries. The design must prove that no callback can enter after the apparent drain; an in-flight counter alone cannot close the race before its first increment. Establish the unregister/invocation guarantee from the pinned libmpv implementation or an independently qualified synchronization mechanism before relying on it. If that guarantee is unavailable, retain the state and report a blocker. Only then send an acknowledgement to the GUI thread, carrying generation, thread/context identities and ordering evidence.

After a verified acknowledgement, close the secondary observer and use the fixture-only OFF-mode Player release barrier above. Prove wakeup and queued hook/event work can no longer dereference the controller, fence and settle the controller worker, then destroy item/view, join worker and destroy core in their valid ownership order. Verify the actual implementation's object and worker ownership before choosing the exact final sequence; do not double-destroy resources still owned by the item. Record each result and preserve the first failure even if cleanup also fails.

Wrong or missing original context, thread mismatch, absent render job, callback uncertainty, failed terminal proof, timeout, or missing acknowledgement makes teardown **blocked**. Do not free on a different context, report success, destroy dependent item/core, or invoke the ordinary destructor. Retain the owner and its dependencies until the existing outer containment takes responsibility. A failed cleanup is not permission to introduce an exit shortcut or silently convert the test into a pass.

## Failure paths and offline proof before any native run

Drive the same injected cleanup coordinator through success and failures immediately after binding, while A is active, and after the scenario Stop has been accepted. Each path must retain the owner, preserve its original verdict and attempt each eligible cleanup action once in order. Test both ordinary failure returns and exceptions so no early assertion bypasses the coordinator. If a failure occurs before a context exists, explicitly prove the no-context branch; never manufacture a Qt-only context as a substitute.

Pure tests with fake resources and controlled callbacks must cover:

- Exact-once free and GUI acknowledgement only after original-thread/context validation, terminal proof, closure and drain; no acknowledgement before free and pointer clear.
- Wrong or lost context, missing job, timeout, overflow and uncertain callback settlement: no free, no success acknowledgement, no dependent item/core destruction; retain ownership and report blocked to outer containment.
- A callback admitted before closure and a queued callback delivered after closure, including across the attempted destruction boundary: both are accounted for, no work touches a retired owner, and free cannot precede the drain. Include the pre-increment race in the proof, not just a counter test.
- OFF-mode queued Player event and delayed hook continuations after release begins: neither accesses a released controller or core, and controller-worker fence and secondary-observer closure precede destruction.
- Actual Stop outcome propagation for accepted, guard rejection, unavailable handle and command error; cleanup Stop, if needed, stays separately labelled. A failed original result remains failed even when cleanup succeeds.

Only after these tests, source-aware review of the pinned callback guarantee, and explicit authorization may a separately bounded native qualification be designed. No result here establishes actual render-thread separation, terminal behavior, callback quiescence, or user-visible recovery.
